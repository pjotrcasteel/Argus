# M1.5 — Offline cohorts of independent ARGUS playtests

## Purpose

Compare **technical/perception observations** from multiple *independent* runs without claiming that browser activity means the player won or that gameplay balance has been scientifically established.

This works locally with current-version `summary.json` files (generated by `Argus.Runner`). It never contacts WyrmForge or requires a paid API.

## Folder format

```text
results/
  experiments/
    run-001/
      summary.json       # actual ARGUS output, required
      experiment.json    # manually specified experiment metadata, optional
      trace.jsonl        # original evidence, not read by the report yet
      frame-0000.png     # original evidence, not read by the report yet
    run-002/
      summary.json
      experiment.json
```

Example `experiment.json` (replace placeholders with actual observed/provided values; **never invent a game version**):

```json
{
  "gameVersion": "verified-version-or-release-identifier",
  "gameProfile": "WyrmForge mobile visual baseline",
  "viewport": "390x844",
  "policyVersion": "checked-in ARGUS SHA"
}
```

If any metadata is missing, or versions/profiles/viewports/policies differ, `isMatchedCohort` is **false** and the report is expressly **descriptive only**. Matching metadata is necessary, not sufficient, for valid gameplay comparison: different procedural worlds, seeds, device performance or starting player states may still undermine causal claims.

## Run

```bash
dotnet restore Argus.slnx
dotnet build Argus.slnx
dotnet test tests/Argus.Tests/Argus.Tests.csproj
dotnet run --project src/Argus.Reporter -- --runs results/experiments --output results/cohorts/demo
```

Outputs:

- `cohort.json`: per-run evidence, totals, visual-gate Wilson 95% interval and matched-metadata flag.
- `cohort.md`: human-readable, clearly qualified summary and a table of all runs.

Reports are local, ignored under `results/`. Deterministic run order. Maximum **10,000** records per report. Missing counters (including camera/motion fields), inconsistent booleans/counts, bad JSON and duplicate run-directory IDs fail instead of silently contaminating the cohort.

## How to interpret metrics

- `playerLocatedFrames / frames`: *coverage of inferred player location*, not actual ground-truth detection accuracy.
- `cameraEstimatedFrames / playerLocatedFrames`: how often usable camera motion was inferred when a player candidate was seen. Unknown movement is not zero movement.
- `meetsVisualCombatGate`: the existing **smoke-test** threshold (menu interaction, two route clicks, three inferred player frames), **not victory or successful combat**.
- The Wilson interval applies *only* to the observed visual gate proportion. No balance/UX significance or real win probabilities are computed.
- `terminalStops`: a visible result/progression screen was detected; this **does not distinguish victory and death**.
- Before real balancing work, add held-out human-verified labels for actual outcomes, repeated comparable conditions and a stronger quality gate.
